# VaticTrader — Render Deployment

A real backend (Express + Postgres) behind the VaticTrader app, packaged as a
one-click Render Blueprint. This replaces the in-memory-only storage with
actual persistence: real accounts (bcrypt-hashed passwords), shared data
(Community, follows, waitlist) that's genuinely shared across everyone who
visits the deployed site, and a real broker API integration (Alpaca paper
trading — see below).

## What's in here

```
render.yaml       — the Blueprint: defines the web service + Postgres together
server/
  server.js       — Express app: serves the frontend, the storage/auth API,
                      and the Alpaca broker integration
  schema.sql       — Postgres schema (users, sessions, key-value tables,
                      encrypted broker credentials)
  package.json
public/
  index.html       — the VaticTrader app, with its storage layer wired to
                      call the backend above (falls back gracefully if no
                      backend is present, so this file still works standalone too)
```

## Real broker integration: Alpaca (paper trading)

One broker on the Brokers page — Alpaca — is a genuine API
integration, not a simulation like the other four (eToro, Interactive
Brokers, MetaTrader 5, TradeStation remain intentionally simulated; building
real integrations with each would need separate real credentials for each
that only you can provide).

**What "real" means here specifically:** entering your own Alpaca API Key ID
and Secret Key makes the server call Alpaca's actual Trading API
(`https://paper-api.alpaca.markets` by default) to verify the credentials
and fetch your real account balance, buying power, and status. A connected
account can send a real (paper) test order. This is Alpaca's paper-trading
environment specifically — free, uses simulated money, and is explicitly
designed by Alpaca for exactly this kind of algo-trading development use
case. It is not live trading with real money unless you deliberately
override `ALPACA_BASE_URL` to Alpaca's live domain with live credentials,
which nothing in this app's UI does for you.

**To use it:** get free paper-trading API keys at
[alpaca.markets](https://alpaca.markets) (anyone globally can sign up with
just an email), then use the "Connect" button on the Alpaca card.

**Credential security:** your Secret Key is encrypted (AES-256-GCM) before
being stored in Postgres and is never sent back to your browser after the
initial connection — the `ENCRYPTION_KEY` environment variable that protects
this is auto-generated by Render at deploy time (see `render.yaml`).

**Honest limitation on testing:** this integration was built and tested
against a local mock server that precisely replicates Alpaca's real,
documented API response and error shapes — not against Alpaca's actual
production servers, since this development environment has no network path
to reach them. The request format, headers, and response parsing are
verified correct against Alpaca's real API spec; the very first real
connection you make is the first time this code talks to Alpaca's actual
servers. If something doesn't work exactly as expected on your first real
connection, that's the specific risk this gap leaves open.


## Deploy — 3 steps, then it's genuinely one click

Render Blueprints deploy from a GitHub repo, so the repo has to exist first.

**1. Push this to a new GitHub repo:**
```bash
cd vatictrader-render-deploy
git init
git add .
git commit -m "VaticTrader with Postgres backend"
git remote add origin https://github.com/YOUR_USERNAME/vatictrader.git
git push -u origin main
```

**2. Deploy on Render:**
- Go to the [Render Dashboard](https://dashboard.render.com) → **New → Blueprint**
- Connect the repo you just pushed
- Render reads `render.yaml` and shows you both resources it's about to
  create (the web service and the database) — click **Apply**
- That's genuinely it. Render provisions the Postgres database, wires its
  connection string into the web service automatically (via `fromDatabase`
  in `render.yaml`), runs `npm install`, and starts the server.

**3. Nothing — the database sets itself up.**
On boot, `server.js` reads `schema.sql` and applies it automatically (every
statement uses `CREATE TABLE / INDEX IF NOT EXISTS`, so this is safe to run
on the very first deploy *and* on every restart afterward). If the database
isn't quite ready yet when the web service starts — a real possibility the
first time both are created together — the server retries for up to 30
seconds before giving up, so this isn't a race condition you need to think
about. There is no manual `psql` step. This was tested against a genuinely
empty, freshly created database before being handed to you (see "Honest
notes" below).

Once deployed, the app at your `*.onrender.com` URL has real accounts and
real shared data from the first request.

## Honest notes

- **A significant, previously-undiscovered bug was found and fixed while
  building this**: every confirm-style modal in the app (delete strategy,
  disconnect broker) had its Cancel/Confirm buttons silently non-functional,
  caused by a `stopPropagation()` call that blocked the click-delegation
  system the whole app runs on. This predates the broker integration work —
  it was only caught because building and testing the real Alpaca disconnect
  flow required actually clicking through a confirm modal end-to-end, which
  no earlier testing had done. Fixed across all 5 affected modals and
  re-verified on three independent flows (Alpaca disconnect, strategy
  deletion, and the Cancel button itself).

- **Free tier cold starts:** on Render's free plan, the web service sleeps
  after 15 minutes of inactivity. The first request after that takes
  20–50 seconds to wake up. Fine for testing; upgrade to the $7/month
  Starter plan before sharing the link widely if that matters to you.
- **Free Postgres expires after 30 days** with no warning. This is a Render
  policy, not something in this codebase — upgrade the database plan before
  that point if you want to keep the data.
- **The demo account still works** — clicking "Try the shared demo account"
  now creates (or logs into) a real `demo`/`demo` account in Postgres the
  first time anyone uses it on a fresh deployment, then reuses it after that.
- **Schema setup is fully automatic** — verified by starting the server
  against a genuinely empty, freshly created Postgres database and
  confirming all four tables (`users`, `sessions`, `kv_shared`,
  `kv_personal`) were created with zero manual steps, then confirmed a
  second boot against the now-populated database doesn't error either.
- **This was tested end-to-end** against real Postgres before being handed
  to you: registration, login from a completely separate browser session,
  building a strategy, and confirming it survives a hard page reload — all
  verified working, not just written.
- **What this does NOT add:** real broker connections are still fully
  simulated, exactly as before. This deployment adds real accounts and real
  shared data — it does not add real trading.


## Stripe (subscription fees only)

Stripe is used only to charge VaticTrader users for Starter ($19/mo) and Pro ($49/mo). It never touches trades or broker funds.

1. In Stripe, copy your secret key (Developers > API keys) into `STRIPE_SECRET_KEY` on Render.
2. Add a webhook endpoint at `https://YOUR-APP.onrender.com/api/billing/webhook` with events `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`. Copy its signing secret into `STRIPE_WEBHOOK_SECRET`.
3. Set `APP_BASE_URL` to your service URL.
4. Enable the Customer Portal in Stripe (Settings > Billing > Customer portal) so users can manage or cancel.
5. For live mode, create the same two monthly prices in live mode and replace `STRIPE_PRICE_ID_STARTER` / `STRIPE_PRICE_ID_PRO`.

Test mode price IDs are prefilled in `render.yaml`. Test card: 4242 4242 4242 4242.

## Real market data for backtests

Backtests use real historical prices when they can get them, and say so on the results page (REAL DATA with source and date range, or SIMULATED DATA).

1. US stocks and ETFs: your own connected Alpaca account (official, keyed).
2. Everything else (global stocks, forex, crypto, commodities, indices): Yahoo Finance's public chart endpoint.
3. Anything neither can serve (custom tickers, some exchanges): the built-in simulated model, clearly labelled.

Important: the Yahoo endpoint is unofficial and intended for personal use. Before charging customers, switch to a licensed provider (Polygon, Twelve Data, EODHD) by replacing `fetchYahooHistory` in `server/server.js`, or set `DISABLE_YAHOO=1` to use Alpaca only. Env vars: `DISABLE_YAHOO`, `MARKET_DATA_YAHOO_BASE`, `ALPACA_DATA_BASE_URL`.

## Risk limits

Each user can set a maximum daily loss, a cap per strategy entry, a maximum number of open positions and a maximum deployed percentage. The live engine enforces them on every new entry (`applyRiskLimits` in `server/server.js`, table `risk_limits`). Limits only restrict new entries; they never close existing positions.

## Strategy chat with live indicators

Every strategy page has a chat panel next to live indicator readings (`POST /api/strategy/indicators`, refreshed every 30 seconds). Readings are computed with the same indicator code the live engine uses, on the latest real bars. Without an `ANTHROPIC_API_KEY` the chat answers from the readings and strategy settings with built-in logic. With a key, `POST /api/ai/strategy-chat` gives free-form answers grounded in the same snapshot (60 messages per user per hour). The assistant only describes readings and rules. It never predicts prices, advises trades or places orders. Yahoo-sourced quotes can be delayed, and the panel says so.

## Live indicator chart

Above the chat, each strategy page draws a live chart from the same endpoint (`POST /api/strategy/indicators` with `chart: true`): the last 120 real bars as candles, price-scale indicators (Bollinger, Keltner, moving averages, VWAP, breakout levels) drawn over price, and oscillators (RSI, MACD, Stochastic, ADX, CCI and the rest) in their own panes with your threshold as a dashed line. Bars where every entry condition was met are shaded and marked. Hover shows the values for any bar. It refreshes with the 30 second poll, and has the same data source and delay caveats as the chat. Custom equations are checked in the conditions list but not drawn.

## AI Portfolio Agent (Pro)

The Portfolio page review now reads your real money: broker equity, cash and open positions, what each strategy has actually done with real fills, the backtest each was built on, and your risk limits (`POST /api/ai/portfolio-agent`). A rule-based review always runs and needs no key. It flags a tripped or missing risk limit, a day loss over 2%, leverage, a position over 40% of exposure, idle cash, strategies losing real money, real results far below their backtest, and long and short strategies on the same symbol. With `ANTHROPIC_API_KEY` set, the model writes the final review from those same computed findings and cannot add numbers of its own. If the AI step fails the rule-based review is returned. It never predicts prices or trades.

## Notifications, journal, alerts, security, records
- **Notifications**: every fill, exit, risk trip, broker problem and alert lands in the in-app bell. Optional email through Resend (`RESEND_API_KEY`, optional `MAIL_FROM`) and Telegram (`TELEGRAM_BOT_TOKEN` from @BotFather; users link with a one-time `/start CODE`). A daily summary is sent at the hour each user picks.
- **Go-live safety**: a one-time risk disclosure must be accepted (Settings, Trading safety) and the user types GO LIVE to confirm; the server enforces the disclosure on `/api/live/deploy`. There is no minimum paper-trading period.
- **Backtest honesty**: backtests subtract fees and slippage (defaults 0.03% and 0.02% per side, editable on the strategy page), report an earlier-70% vs recent-30% split and plain warnings. Strategy pages compare real results with the backtest.
- **Trade journal**: each real entry stores a snapshot of the conditions and the last 60 bars.
- **Alerts**: watch conditions without deploying (3 on free, 25 on paid or trial), checked every minute, no orders ever placed.
- **Security**: TOTP two-factor sign-in with 8 one-time recovery codes (manual key entry, no QR code) and a sessions list with remote sign-out.
- **Records**: CSV export and a printable yearly statement.
- **Also**: gzip, status banner, skeleton loaders, plan usage meter, trial countdown, seven-step first-run checklist, a market-hours panel (regular sessions, no holiday calendar), Arabic labels on the new screens.
- Env: `RESEND_API_KEY`, `MAIL_FROM`, `TELEGRAM_BOT_TOKEN`. `DISABLE_LIVE_TICK=1` also disables alert and summary schedulers.


## What-if replay, calendar, Strategy Index, auto-pause

**Pre-trade "what if" replay.** On a strategy page and inside the go-live window, "Re-run" replays the last 30 days of price history through the strategy's rules and lists the trades it would have taken. Limits: entries are filled at the signal bar's close, and take-profit/stop-loss are checked against later highs and lows (stop first when both hit). Real fills, spreads and gaps differ. How far back it can look depends on what the data source returns for the timeframe; the panel says when history was shorter than 30 days.

**Calendar warnings.** A dashboard widget, a banner, and a note on the strategy page warn when a symbol you hold or trade has an event that day. Built in: FOMC, ECB and Bank of England rate-decision dates, listed up to 2026-12-31 (add or replace dates with `MACRO_EVENTS_JSON`, a JSON array). CPI, jobs and other releases are not included. Earnings need a free `FINNHUB_API_KEY`; without it the earnings part is simply off. A "calendar" notification is sent at most once per event per day.

**Strategy Index.** Community > Strategy Index ranks published strategies using closed trades the platform placed on Alpaca, not backtests. Strategies need at least 5 closed trades to be ranked, and anything under 20 is flagged as a small sample. Score is average per-trade return weighted by sample size. The paper/real label comes from the owner's current broker connection, so it can change if they reconnect. Strategies published before this update are matched by owner + name + symbol.

**Keep trading and auto-pause (opt-in).** By default a go-live is still a single trade. In the go-live window you can tick "keep trading", which re-arms the strategy after each close (it must see its entry rule turn false before entering again) and pauses it after N consecutive losing trades (default 3, range 1 to 50). You can change N or turn it off from the strategy page. Resuming restarts the loss count. This applies to real broker (Alpaca) strategies only; demo trading runs in the browser and is not covered. This places repeated real orders, so it is worth testing on paper first.

## Bring your own AI key, and Stripe from the Admin page

**Customer AI key.** Settings, AI assistant lets each customer connect their own AI account (Anthropic, OpenAI, or any OpenAI-compatible endpoint with a model name and optional base URL). It powers the AI Portfolio Agent, Describe a strategy, Check logic with AI and the strategy chat. The key is encrypted with AES-256-GCM (`ENCRYPTION_KEY`), never sent back to the browser (only the last 4 characters), and a customer's own key takes priority over the platform `ANTHROPIC_API_KEY`. Custom endpoints must be public https; private and loopback addresses are blocked (set `AI_ALLOW_PRIVATE_URLS=1` only for local testing). Errors are scrubbed so a key never appears in a message. The customer's provider bills them directly. The AI Portfolio Agent is still a Pro feature (trial counts as Pro), and the key does not change that. Endpoints: `GET /api/ai/status`, `GET/PUT/DELETE /api/ai/config`, `POST /api/ai/config/test`.

**Stripe from Admin.** Admin, Stripe billing stores the secret key, webhook signing secret, Starter and Pro price IDs and an optional app address, encrypted in the `app_settings` table. Saved values win over the `STRIPE_*` environment variables, which remain a fallback, so existing deployments keep working. The page shows the exact webhook URL to paste into Stripe, a Test connection button, and asks for explicit confirmation before saving a live key. Plans are still subscriptions only through Stripe Checkout. Endpoints: `GET/PUT /api/admin/stripe`, `POST /api/admin/stripe/test` (admin only). Only the founder-code account is an admin.

## Portfolio is real data only

The Portfolio page and the Home totals use one source, `GET /api/portfolio/real` (broker account, positions and genuine fills), so both always show the same numbers. The simulated $10,000 planning view, blended backtest figures and position-size exposure were removed from Portfolio. `GET /api/portfolio/trades-curve?period=1D|1W|1M|3M|1A[&strategyId=]` builds the equity curve from trades VaticTrader placed with real orders only (cumulative realized P&L from `live_trade_log`, plus open P&L at the broker's current prices). It is not the whole broker account, so deposits, withdrawals and trades placed elsewhere never move it. The same panel is used on Home, Portfolio and a live strategy's own page. Exposure and concentration are computed from real broker positions. Demo-mode strategies stay simulated by design and are labelled as practice runs, excluded from every Portfolio figure. Only Alpaca is read today. eToro and other brokers verify credentials but have no balance or position reading wired in, so they do not appear here yet.

## Real market prices and the strategy library

**Prices.** The ticker, Home snapshot, watchlist and Markets page no longer use invented numbers. `GET /api/market/quotes?symbols=A,B,...` (max 40 per call, 40 calls per user per minute) returns price, previous close, daily change and a short sparkline from Yahoo Finance's public feed, cached 45 seconds. US stocks can be delayed up to 15 minutes, and the page says so with the time of the last price. The page loads prices only for cards on screen, so the full 874-instrument list never hits the feed at once. A symbol Yahoo cannot price shows "N/A", never a made-up value. Demo-mode trading and backtests that fall back to simulated bars still use the built-in simulated model and are labelled SIMULATED. Yahoo's feed is unofficial, so for production consider a licensed data provider and set `DISABLE_YAHOO=1` to turn this off.

**Ready-made strategies.** `TEMPLATE_RECIPES` in `public/index.html` holds classic, widely studied rule sets (Wilder RSI, Bollinger Bands, MACD, EMA and SMA crossovers, Turtle-style Donchian breakouts, Keltner, Stochastic, CCI, MFI, ADX and Aroon filters, VWAP) expanded across liquid US stocks, forex pairs and crypto into 227 templates, alongside the original 50. Cards show the origin of each idea and are filterable by market and style. No card states a win rate or return, and forex rules avoid volume conditions because spot forex feeds carry none. Add more by adding a recipe.
